# Домашнє завдання до лекції 6

**Тема:** Організація пам'яті: ієрархія, кеш і віртуальна пам'ять  

## 1. Ієрархія пам'яті

| Рівень | Орієнтовний обсяг | Швидкодія |
| --- | --- | --- |
| Регістри процесора | Одиниці–десятки регістрів | Найвища, частки такту |
| Кеш L1 | Десятки кілобайт | Дуже висока |
| Кеш L2 | Сотні кілобайт — одиниці мегабайт | Висока |
| Кеш L3 | Одиниці — десятки мегабайт | Середня серед кешів |
| Оперативна пам'ять (DRAM) | Одиниці — десятки гігабайт | Помірна |
| SSD/HDD | Сотні гігабайт — терабайти | Найнижча |

Схема згори вниз: **регістри → L1 → L2 → L3 → DRAM → SSD/HDD**. Чим далі рівень від процесора, тим більший його обсяг і нижча швидкодія; наведені в лекції обсяги є орієнтовними.

## 2. Послідовний і стовпчиковий обхід масиву C

Мова C зберігає двовимірний масив у пам'яті по рядках. Послідовний обхід:

```c
for (int i = 0; i < 100; ++i)
    for (int j = 0; j < 100; ++j)
        sum += a[i][j];
```

Такий порядок читає сусідні елементи поспіль і використовує **просторову локальність**, тому зазвичай спричиняє менше промахів кешу.

Стовпчиковий обхід:

```c
for (int j = 0; j < 100; ++j)
    for (int i = 0; i < 100; ++i)
        sum += a[i][j];
```

Тут кожен крок переходить на наступний рядок, тобто приблизно на `100 * sizeof(int) = 400` байтів. Це гірше використовує рядки кешу й може збільшити кількість промахів.

## 3. Витіснення брудного рядка кешу

За **write-back** змінені дані спершу лишаються в кеші й рядок позначається `dirty`. Під час його витіснення кеш-контролер має записати рядок назад у нижчий рівень пам'яті, і лише після цього місце можна повторно використати.

За **write-through** кожен запис у кеш одночасно передається до нижчого рівня (можливо, через буфер запису). Тому нижчий рівень уже містить актуальні дані й окремий запис у пам'ять саме через витіснення не потрібен.
