# Самостійна робота №7

**Дисципліна:** Комп'ютерні та мікропроцесорні системи, організація комп'ютерних мереж  
**Тема:** Порівняння систем команд x86, ARM і RISC-V  
**Варіант:** 4 — перевірка, чи є число простим  
**Компілятор:** GCC 15.1, `-O0`  

## 1. Функція C

```c
int is_prime(int n) {
    if (n < 2) return 0;
    for (int divisor = 2; divisor <= n / divisor; ++divisor) {
        if (n % divisor == 0) return 0;
    }
    return 1;
}
```

Перевірка `divisor <= n / divisor` не використовує `divisor * divisor`, тому не переповнюється для великих додатних `n`. Приклади: `is_prime(29) == 1`, `is_prime(35) == 0`.

## 4. Висновок

У цьому прикладі GCC 15.1 з `-O0` згенерував 26 інструкцій для x86-64, 32 для ARM64 і 40 для RV64GC. В x86-64 команда `idiv` може брати дільник безпосередньо з пам'яті. ARM64 завантажує операнди в регістри перед `sdiv`, а RISC-V використовує окремі `lw` і `sw` разом із командами ділення та остачі. Частину різниці створюють збереження локальних змінних у стеку без оптимізацій. Це результат одного компілятора й однієї функції, а не доказ, що RISC завжди повільніший.

## Контрольні запитання

1. **Чому в RISC-архітектурах арифметичні команди не можуть напряму звертатися до пам’яті?**  
   У моделі load/store арифметичні команди працюють лише зі значеннями в регістрах. Дані з пам’яті
   спочатку завантажуються командами `load`, а результат за потреби записується командами `store`.
   Такий поділ спрощує формат і декодування інструкцій та допомагає будувати регулярний конвеєр.

2. **Чи завжди більша кількість інструкцій означає повільніше виконання? Від чого ще залежить час?**  
   Ні. Час залежить також від кількості тактів на інструкцію, тактової частоти, затримок пам’яті,
   кешу, передбачення переходів, конвеєра, залежностей між командами й можливостей паралельного
   виконання. Одна складна інструкція може займати багато тактів, тоді як кілька простих інструкцій
   можуть виконуватися конвеєрно.

3. **Наведіть приклад, коли складна CISC-команда x86 виконує роботу кількох RISC-команд.**  
   У наведеному x86-64 коді `idiv DWORD PTR [rbp-4]` читає дільник з пам’яті й виконує ділення
   однією інструкцією. У load/store архітектурі для цього окремо завантажують дільник у регістр,
   а потім виконують команду ділення, наприклад `lw` і `divw` у RISC-V.
