# Практична робота №9 — варіант 4

## Тема

Статична й динамічна маршрутизація, NAT.

## Мета

Налаштувати статичну маршрутизацію між трьома маршрутизаторами, перевірити шлях і таблиці маршрутів, налаштувати OSPF відповідно до варіанта та реалізувати PAT для виходу внутрішніх вузлів у зовнішню мережу.

## Вихідні дані варіанта

| Параметр | Значення |
| --- | --- |
| Мережа за R1 | `10.1.0.0/24` |
| Мережа за R2 | `10.2.0.0/24` |
| Зовнішня мережа за R3 | `203.0.113.24/29` |
| Протокол динамічної маршрутизації | OSPF |

Транзитні мережі між маршрутизаторами не задані у варіанті, тому для лабораторної схеми виділено дві неперекривні мережі `/30` з приватного адресного простору: `10.255.0.0/30` і `10.255.0.4/30`.

## Топологія й адресний план

```text
PC-A ─ R1 G0/0
       R1 G0/1 ── 10.255.0.0/30 ── R2 G0/0
                                      R2 G0/2 ── 10.255.0.4/30 ── R3 G0/0
                                      R2 G0/1 ── PC-B
R3 G0/1 ── SW ─ PC-EXT
```

У симуляції використано маршрутизатори Cisco 2911. Через автоматичний вибір кабелів фактичне підключення R2 відрізняється від початкового прикладу: `G0/1` з'єднаний із PC-B (LAN B), а `G0/2` — з R3. Адресний план збережено, ролі інтерфейсів узгоджено з фактичними з'єднаннями.

| Пристрій / інтерфейс | IP-адреса | Маска | Призначення |
| --- | --- | --- | --- |
| R1 G0/0 | `10.1.0.1` | `255.255.255.0` | Шлюз LAN A |
| PC-A | `10.1.0.10` | `255.255.255.0` | Кінцевий вузол LAN A, GW `10.1.0.1` |
| R1 G0/1 | `10.255.0.1` | `255.255.255.252` | Транк R1–R2 |
| R2 G0/0 | `10.255.0.2` | `255.255.255.252` | Транк R1–R2 |
| R2 G0/2 | `10.255.0.5` | `255.255.255.252` | Транк R2–R3 |
| R3 G0/0 | `10.255.0.6` | `255.255.255.252` | Транк R2–R3; NAT inside |
| R2 G0/1 | `10.2.0.1` | `255.255.255.0` | Шлюз LAN B |
| PC-B | `10.2.0.10` | `255.255.255.0` | Кінцевий вузол LAN B, GW `10.2.0.1` |
| R3 G0/1 | `203.0.113.25` | `255.255.255.248` | Зовнішній інтерфейс; NAT outside |
| PC-EXT | `203.0.113.26` | `255.255.255.248` | Зовнішній тестовий вузол, GW `203.0.113.25` |

## Хід роботи

### 1. Налаштування адрес інтерфейсів і тест зв'язку із сусідніми вузлами

На всіх інтерфейсах установити адреси з таблиці та виконати `no shutdown`. На ПК задати IP, маску й шлюз. Перевірити з маршрутизаторів ping до сусідніх адрес транку: R1 → `10.255.0.2`, R2 → `10.255.0.6`, R3 → `10.255.0.5`.

Приклад конфігурації R1:

```text
enable
configure terminal
interface gigabitEthernet 0/0
 ip address 10.1.0.1 255.255.255.0
 no shutdown
exit
interface gigabitEthernet 0/1
 ip address 10.255.0.1 255.255.255.252
 no shutdown
end
show ip interface brief
```

R2:

```text
enable
configure terminal
interface gigabitEthernet 0/0
 ip address 10.255.0.2 255.255.255.252
 no shutdown
exit
interface gigabitEthernet 0/2
 ip address 10.255.0.5 255.255.255.252
 no shutdown
exit
interface gigabitEthernet 0/1
 ip address 10.2.0.1 255.255.255.0
 no shutdown
end
show ip interface brief
```

R3:

```text
enable
configure terminal
interface gigabitEthernet 0/0
 ip address 10.255.0.6 255.255.255.252
 no shutdown
exit
interface gigabitEthernet 0/1
 ip address 203.0.113.25 255.255.255.248
 no shutdown
end
show ip interface brief
```

### 2. Статичні маршрути

На R1 додати маршрути до мереж LAN B та зовнішньої мережі:

```text
configure terminal
ip route 10.2.0.0 255.255.255.0 10.255.0.2
ip route 203.0.113.24 255.255.255.248 10.255.0.2
end
show ip route
```

На R2:

```text
configure terminal
ip route 10.1.0.0 255.255.255.0 10.255.0.1
ip route 203.0.113.24 255.255.255.248 10.255.0.6
end
show ip route
```

На R3:

```text
configure terminal
ip route 10.1.0.0 255.255.255.0 10.255.0.5
ip route 10.2.0.0 255.255.255.0 10.255.0.5
end
show ip route
```

У таблицях непрямі мережі мають позначатися `S` (static). Перевірити ping PC-A → PC-B, PC-A → PC-EXT і PC-B → PC-EXT. З PC-A виконати `tracert 203.0.113.26`; маршрут має пройти через R1, R2 і R3 до зовнішньої LAN.

### 3. OSPF для варіанта 4

Щоб перевірити саме протокол, заданий варіантом, видалити зазначені вище статичні маршрути перед запуском OSPF; інакше статичний маршрут із нижчою адміністративною відстанню перекриватиме OSPF.

На R1 видалити його статичні маршрути й увімкнути OSPF:

```text
configure terminal
no ip route 10.2.0.0 255.255.255.0 10.255.0.2
no ip route 203.0.113.24 255.255.255.248 10.255.0.2
router ospf 1
 network 10.1.0.0 0.0.0.255 area 0
 network 10.255.0.0 0.0.0.3 area 0
end
show ip ospf neighbor
show ip route
```

На R2:

```text
configure terminal
no ip route 10.1.0.0 255.255.255.0 10.255.0.1
no ip route 203.0.113.24 255.255.255.248 10.255.0.6
router ospf 1
 network 10.2.0.0 0.0.0.255 area 0
 network 10.255.0.0 0.0.0.3 area 0
 network 10.255.0.4 0.0.0.3 area 0
end
show ip ospf neighbor
show ip route
```

На R3:

```text
configure terminal
no ip route 10.1.0.0 255.255.255.0 10.255.0.5
no ip route 10.2.0.0 255.255.255.0 10.255.0.5
router ospf 1
 network 10.255.0.4 0.0.0.3 area 0
 network 203.0.113.24 0.0.0.7 area 0
end
show ip ospf neighbor
show ip route
```

Після встановлення сусідства OSPF на R1 та R3 мають з'явитися маршрути `O` до віддалених LAN. Повторити ping і `tracert`. Топологія лінійна й не має альтернативного шляху: при обриві єдиного транку OSPF прибере недосяжні маршрути, але обійти обрив без резервного каналу не зможе. Статичний маршрут сам не перебудовується й лишається в конфігурації, доки його не видалити або не налаштувати окремий механізм резервування.

### 4. NAT із перевантаженням портів (PAT)

Налаштувати NAT на R3: інтерфейс до R2 — inside, інтерфейс у зовнішню мережу — outside. ACL дозволяє лише дві внутрішні мережі варіанта.

```text
configure terminal
access-list 1 permit 10.1.0.0 0.0.0.255
access-list 1 permit 10.2.0.0 0.0.0.255
interface gigabitEthernet 0/0
 ip nat inside
exit
interface gigabitEthernet 0/1
 ip nat outside
exit
ip nat inside source list 1 interface gigabitEthernet 0/1 overload
end
```

З PC-A і PC-B надіслати ping до PC-EXT `203.0.113.26`, потім на R3 виконати:

```text
show ip nat translations
show ip nat statistics
```

У таблиці трансляцій знайти записи для джерел `10.1.0.10` і `10.2.0.10`. Для перевірки вхідного напрямку зовнішній вузол не має створеного NAT-запису, який зіставляє нове з'єднання з конкретним внутрішнім сервером; без статичної трансляції або port forwarding таке з'єднання не доставляється до приватного вузла. PAT створює динамічні записи для з'єднань, ініційованих зсередини, а не правило для довільних нових вхідних з'єднань.

### Пояснення полів NAT

| Поле | Значення |
| --- | --- |
| Protocol | Протокол потоку (наприклад, `icmp`, `tcp` або `udp`). |
| Inside local | Приватна адреса (і порт/ідентифікатор) внутрішнього вузла до трансляції. |
| Inside global | Публічна адреса R3 і виділений PAT порт/ідентифікатор, якими внутрішній вузол представлений назовні. |
| Outside local | Адреса зовнішнього вузла, видима з внутрішньої мережі. |
| Outside global | Реальна адреса зовнішнього вузла. У цій лабораторії часто збігається з Outside local. |

Точний вигляд рядків залежить від типу трафіку й версії Packet Tracer; зафіксувати власний результат команди.

## Відповіді на контрольні запитання

1. **Чому мережі за двома переходами недоступні одна одній без маршрутизації, навіть якщо сусідні мережі пінгуються?** Успішний ping до сусіднього маршрутизатора підтверджує лише локальне з'єднання. Щоб дійти до віддаленої мережі й повернути відповідь, кожен маршрутизатор на шляху має знати відповідний маршрут або мати маршрут за замовчуванням.
2. **Чим статичний маршрут відрізняється від динамічного при відмові каналу?** Статичний маршрут заданий вручну й не обмінюється інформацією про топологію, тому зазвичай потребує ручного виправлення. OSPF обмінюється станом каналів, виявляє зміну та перераховує таблицю; за наявності альтернативного шляху він може переключити трафік після збіжності.
3. **Які поля містить таблиця NAT і що вони означають?** Типове подання містить Protocol, Inside local, Inside global, Outside local та Outside global. Вони показують транспортний протокол, внутрішню адресу до трансляції й адресу/порт, видимі назовні, а також зовнішню адресу в локальному та глобальному поданні.
4. **Чому PAT дозволяє багатьом вузлам одночасно виходити через одну публічну адресу?** PAT створює окремі записи трансляції й призначає різні зовнішні номери портів або ідентифікатори потоків. За адресою та портом призначення маршрутизатор знаходить відповідного внутрішнього вузла для відповіді.
5. **Що потрібно налаштувати, щоб зовнішній вузол міг ініціювати з'єднання до сервера за NAT?** Потрібне статичне зіставлення або правило port forwarding, що перенаправляє конкретний протокол і зовнішній порт на приватну IP-адресу та порт сервера. Також правила брандмауера мають дозволяти цей трафік.

## Осмислення результату

Статичний маршрут налаштовано вручну та самостійно не дізнається про зміну топології; після втрати каналу адміністратору довелося б виправити або видалити його й за потреби прописати інший шлях. OSPF обмінюється інформацією про стан каналів, тому після збіжності видаляє маршрут через недоступний сегмент і використовує альтернативу, якщо вона існує. PAT записує трансляції для вихідних потоків; для нового вхідного потоку в таблиці немає зіставлення з внутрішнім сервером, тому потрібне окреме правило.

## Критерії оцінювання — самоперевірка на 5

- [ ] Топологія та всі три мережі відповідають варіанту 4.
- [ ] Статичні маршрути забезпечують зв'язність між внутрішньою та зовнішньою мережами.
- [ ] Для OSPF є сусідство й динамічні маршрути; розумію, що без резервного шляху обрив лінійної топології не дає обходу.
- [ ] PAT транслює внутрішній трафік, вивід таблиці пояснено.
- [ ] Пояснено відсутність нових вхідних з'єднань без port forwarding.
- [ ] Є `.pkt`, трасування й скріншоти результатів.

## Висновок

У роботі побудовано маршрутизацію між мережами `10.1.0.0/24`, `10.2.0.0/24` та зовнішнім сегментом `203.0.113.24/29`. Спочатку зв'язність перевіряється статичними маршрутами, потім — OSPF відповідно до варіанта 4. На R3 налаштовано PAT, завдяки якому внутрішні вузли можуть ініціювати обмін із зовнішньою мережею через одну адресу. Нові вхідні з'єднання потребують окремого правила трансляції.
